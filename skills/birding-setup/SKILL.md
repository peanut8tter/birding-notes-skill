# birding-setup — 开始或继续你的观鸟记录

你（AI）要带一位**你对他一无所知的用户**走完配置。他可能从没记过观鸟、可能已在 Notion 里有自己的表、也可能记在 Excel / eBird / 别的 App 里；他可能不懂 API、token、数据库这些词；他想记的内容也和别人不同。目标：约 5–10 分钟后，他的 Notion 里有一个**按他的习惯定制**的观鸟记录库，并且已经有一条**完整**的条目摆在眼前。

脚本都在本目录 `scripts/`，只用标准库，输出 JSON：
- `HELPER` = `scripts/setup_helper.py`（配置、连接、建库、导入、批量写字段）
- `TOOLS` = `scripts/entry_tools.py`（给条目写正文、找配图、GBIF 链接、找空条目）

用 `python3 HELPER`（无参数）查看全部命令。

## 铁律
1. **第一条回复必须是自我介绍 + 第一个问题**（见步骤 1），不能一上来就要 token、建表或讲术语。
2. **说人话**。不甩术语：token 叫「一把钥匙」，数据库叫「一张表格」。先说**为什么需要**，再说怎么做。
3. **一次只问一件事**，等回复再继续。每一步做完确认成功再进下一步，并用一句话说「现在已经完成了什么」。
4. **先了解、再动手**：建什么列、写不写正文、要哪些模块、要不要配图，**都由用户的回答决定**，不要替他定。拿不准就给默认选项并说明默认是什么。
5. **不假设用户是谁**：不预设城市、不预设已有数据、不预设在中国、不预设用中文。
6. **只新增，不改动用户已有的东西**：已有的列、已有的页面、已有的数据一律不动、不删。
7. **密钥只通过 HELPER 保存**（先校验，权限 600，存 `~/.config/birding-notes/secrets/`）。绝不写进项目文件，也不在回复里复述。
8. **别把原始 JSON 甩给用户**，翻译成人话；出错说清原因和下一步（见文末「排错」）。
9. **不交空壳**：用户要的是完整条目（`entry_depth` = full），就必须把正文和配图写出来才算完成；写不出的部分如实说明原因，不要悄悄留空。
10. 已完成的步骤不重复问；以 `status` 为准。

## 步骤 0：看现状
```bash
python3 HELPER status
```
- `ready: true` → 不要重走向导。问他想做什么（记新鸟 / 导入旧记录 / 补写还没有正文的条目 / 改设置）。可 `list-rows` 告诉他「你库里已有 N 种」，`TOOLS empty-pages` 看有几种还没正文。
- `ready: false` → 看 `next`，从对应步骤继续，并说「上次已经配好了 X，我们接着做 Y」。
- 没有任何配置 → 步骤 1。

## 步骤 1：自我介绍（第一条回复，必须做）
用自己的话讲清下面四点（别照念，控制在一屏内），然后直接问步骤 2 的第一个问题：

1. **这是什么**：「我可以帮你把看过的鸟记到 Notion。你告诉我鸟名（或把旧记录丢给我），我负责查准学名和分类（对照 AviList 全球名录，不凭记忆瞎写），整理成记录，重复的自动跳过。」
2. **你会得到什么**（用一个具体例子，让他一眼看懂）：
   > 每种鸟在 Notion 里是表格里的一行（名称、学名、英文名、分类、首次观察的时间地点……这些列由你定），点开还可以是一页完整资料：**一张代表性实拍图**，然后是 🐾 性格与行为、🧬 分类考据、🌏 分布与生态、🎵 鸣声、📜 文化与演化（有传世古画的会配上）。这些内容是可选的，你想要哪些我们马上聊。
3. **要多久、需要什么**：约 5–10 分钟；需要一个 Notion 账号（免费版就够）。
4. **接下来怎么走**：「先问你几个问题，了解你平时怎么记，再按你的习惯把东西搭起来。」

没有 Notion 账号 → 先让他去 notion.so 免费注册。目前记录只能存到 Notion，如实告知，别假装有别的选项。

## 步骤 2：了解他的习惯（逐个问，一次一问）

**Q1 · 记过吗？记在哪？**
> 你以前记录过观鸟吗？记在哪里？
> A. 还没开始记 / 想从头开始
> B. 已经在 Notion 里有一张记录表了
> C. 记在别的地方（Excel、eBird、某个观鸟 App、备忘录、微信、纸上……）

- 拿不准、「就记了一点」→ 当 A，之后可导入。
- B 但其实是 Notion 页面里的一段清单（不是表格）→ 当 C。
- B / C 追问一句：大概多少种？（决定后面导入要不要分批、正文写不写全）。C 还要问「现在能拿出来吗」。
- 他说「记过」时，**主动问他现在的记法有什么不满意**（如：学名总出错、没有分类、想要更详细），这决定你重点做什么。

**Q2 · 每次想记哪些信息？**
给他看这张菜单（A、C 用来决定建哪些列；B 用来对照他已有的列，缺的问要不要加）：
> **一定会有**：中文名（或你习惯的名字）、学名
> **常用，建议要**：英文名、目、科（分类）、首次观察日期、首次观察地点
> **可选**：居留型（留鸟 / 夏候鸟 / 冬候鸟 / 旅鸟…，按你的观察地判定）、IUCN 受胁等级、本国保护等级（中国：国家一级 / 二级、三有）、分类数据来源
> **你自己的**：比如天气、同行的人、评分、心情、备注……还有想记的吗？

- 他列的自定义项 → 记下列名和类型（文字 / 数字 / 日期 / 单选 / 链接 / 勾选）；不确定类型就用文字。
- 不在中国观鸟的人，「中国保护等级」没用，建议不要。

**Q3 · 要一页完整资料吗？**
> 每种鸟，你想要：
> ① **只记表格那几列**（最快，之后随时可以补）
> ② **每种鸟还有一页完整资料**（推荐）：实拍图 + 下面这些模块，你选要哪些：
>    - 🐾 **性格与行为**：习性、食性、行为特征，只写可核对的事实要点
>    - 🧬 **分类考据**：拉丁名的词源、在分类系统里的位置
>    - 🌏 **分布与生态**：分布范围 + 全球出现记录链接（GBIF）
>    - 🎵 **鸣声 / 鸣唱**：鸣声描述 + 一段真实录音的链接（需要免费注册 xeno-canto 拿一个 key）
>    - 📜 **文化与演化**：名字典故、诗词民俗、科学史
>    - 🔍 **识别区分**（默认不开）：和相似鸟种怎么分
>
> 默认前五个全开。

- 选 ① → `entry_depth` = basic；选 ② → `full` 并记下模块。
- 选了 🎵 且没有 xeno-canto key：说明那一块**没有 key 就只有文字、没有录音链接**，问他现在去申请（https://xeno-canto.org/account，免费）还是以后再说。
- 说明时间：完整资料每种约 1–3 分钟（要查资料、找图、看图确认）。若他要导入很多种，建议**先全部入库为基础记录，再分批补正文**——我可以说「补下一批」继续。

**Q4 · 配图想要什么？**（仅 ② 时问）
> 页面里的图：
> - **实拍图**（页面第一张，方便认鸟，也是画廊里的缩略图）
> - **古画 / 博物画**（有传世作品的物种才会有，放在「文化与演化」里）
>
> 要哪些？默认都要。（图都来自 Wikimedia Commons，署名和许可证写在图下，我会逐张看图确认是对的物种。）

→ `entry_images`：`both` / `photo` / `art` / `none`。

**Q5 · 两个小问题（可跳过）**
1. 主要在哪观鸟？（城市 / 地区 / 国家）——用来判断留鸟还是候鸟、分布侧重点、录音地偏好。
2. 物种名想用中文还是英文？

**确认方案**：用一小段话复述「我听到的是……」：现在记在哪、要记哪几列、要不要完整资料及哪些模块、配图、观鸟地。问「这样对吗？」他确认后再动手；他改了就按他的。

**保存偏好**（此时不需要 Notion，可立刻存）：
```bash
python3 HELPER set user_preferences.entry_depth full            # 或 basic
python3 HELPER set user_preferences.entry_modules '["behavior","taxonomy","distribution","voice","culture"]'   # 按他的选择；id=识别区分
python3 HELPER set user_preferences.entry_images both           # both / photo / art / none
python3 HELPER set user_preferences.primary_location <城市>      # 跳过则不存
python3 HELPER set user_preferences.regional_focus <地区>
python3 HELPER set user_preferences.regional_focus_country <国家，如 China>
python3 HELPER set user_preferences.name_language zh            # 或 en
```
basic 也要存 `entry_depth`、`entry_images=none`、`entry_modules='[]'`。

## 步骤 3：连接 Notion（所有人都要做）
解释：「要让我能往你的 Notion 里写东西，需要你在 Notion 里创建一个『集成』，它会给你一串密钥，像一把钥匙。这把钥匙只能打开你**明确授权**的页面，别的页面它看不到。」

带用户做（Notion 界面可能是英文，两种叫法都给）：
1. 打开 https://www.notion.so/profile/integrations → 新建集成（New integration）
2. 名称随意（如「观鸟笔记」），类型选**内部 / Internal**，关联到他自己的工作空间 → 保存
3. 复制「内部集成密钥 / Internal Integration Secret」（以 `ntn_` 开头），粘贴给你

```bash
python3 HELPER set-notion-token <token>
```
成功 → 「已连上，集成名叫 XX」。失败 → 多半没复制全，让他重贴。保存后提醒：聊天记录里有这串密钥，介意的话走完向导后可到 Notion 重置。

## 步骤 4：准备存放记录的表格

Notion 的规则：集成默认**看不到任何页面**，要逐个授权。每条路都有这一步，把点击路径讲清楚：
> 在 Notion 打开那个页面/表格 → 右上角「···」→「连接 / Connections」→ 选择刚创建的集成 → 确认。

### 4A 从零开始
1. 请他在 Notion 新建一个**空白页面**（标题如「🐦 观鸟笔记」），按上面路径授权给集成。
2. `python3 HELPER find "观鸟笔记" --pages` 找到它（没找到 → 没授权，或刚建好等几秒重试）。
3. 按 Q2 的回答建表：
   ```bash
   python3 HELPER create-db <页面id> --fields en,order,family,first_date,first_place,residency \
        --extra "天气:text,同行者:text,评分:number" [--lang en] [--title "我的观鸟记录"]
   ```
   `--fields` 只列他选的可选字段（名称、学名必含，不用列）；`--extra` 是他自己的列（类型：text select multi_select date number url checkbox）；他用英文就加 `--lang en`。脚本自动保存配置。
4. 用大白话告诉他表里有哪几列，给出链接（`url`）。「不需要的列，之后在 Notion 里直接删就行。」

### 4B 接入他已有的 Notion 记录表
1. 请他把表授权给集成。
2. `python3 HELPER find "<表名>" --databases`（不知道名字就不带关键词，列出来让他挑）。
3. `python3 HELPER inspect <id>`，把结果**翻译成对照表**给他确认：「你的『Name』列 = 物种名；『Latin name』= 学名……」；识别不出的列明说「这列我不会碰」。**必须让他确认**，他纠正就按他的来。
4. 对照 Q2：他想记而表里没有的列，问要不要新增；强调「只新增列，不改你已有的列和数据」。
5. 保存：
   ```bash
   python3 HELPER set notion.life_list_database_id <database_id>
   python3 HELPER set notion.life_list_data_source_id <data_source_id>
   python3 HELPER map name=<标题列> sci=<学名列> ...     # 以用户确认的对照为准
   python3 HELPER add-fields en order family source      # 仅限用户同意新增的
   ```
6. `python3 HELPER list-rows`：「你已经有 N 种，之后重复的我会自动跳过。」`TOOLS empty-pages` 看有几种还没正文。
7. **他已有的页面不动**：除非他明确要求，不往他旧页面里写正文；只有新记的鸟才按偏好写完整条目。
8. 某列类型不支持（公式、人员、关联等）→ 明说「这列我不会写」。

### 4C 从别处导入（先完成 4A 建新表；他想并入已有表则先做 4B）
1. 问他数据在哪、怎么给你：
   - **eBird**：My eBird → Download My Data，邮件收到 `MyEBirdData.csv`。每次观察一行，需按物种合并，取**最早**的日期及当时地点；有 `Scientific Name`、`Common Name`。
   - **Excel / 表格**：导出 CSV 或直接给；先看表头，和他确认各列含义。
   - **其他观鸟 App**：看能否导出；不能就让他复制清单或截图（你的环境支持看图才处理截图）。
   - **备忘录 / 微信 / 纸质**：把文字贴过来。
2. 整理成 JSON 数组，**每个物种一项**，键用标准字段：`name`、`sci`、`first_date`、`first_place`、`residency`……，自定义列直接用列名当键。
   - 只有中文名 / 英文名、没学名：先给候选学名，**必须**用 `skills/avilist-bird-lookup`（`verify_candidates.py`，数据 `assets/avilist_species.json`）校验；对不上或有歧义的不要猜，单独列出问他。
   - 日期认不出就留空，不要编。
3. 给他看**摘要**再动手：共 N 种、前 5 条示例、有问题的 M 条及原因。等他确认。
4. 预演 `python3 HELPER add-rows <文件> --dry-run`，无误后正式 `python3 HELPER add-rows <文件>`。自动按学名补全英文名 / 目 / 科 / 数据来源（AviList v2025）并去重，可重复运行；约 0.35 秒/条，几百条先说明要几分钟。
5. 汇报：新增几条、跳过几条重复、哪些要他核对（`notes`）。
6. **导入后的正文**：`entry_depth` = full 时，问他「这 N 种要现在全部写完整资料，还是先放着、之后分批补？」默认建议分批（每批 5–10 种），并告诉他随时说「补下一批」。

## 步骤 5：一起记下第一只鸟（让他看到成果，必须做完整）
A / C（以及 B 想试试的）：「说一种你最近见到的、或最想记的鸟，我现在记给你看。」

1. 物种身份有歧义先问清（「麻雀」「白鹭」这类泛称）。
2. 用 `skills/avilist-bird-lookup` 查证学名，不凭记忆写。
3. `add-rows` 写字段，拿到返回的 `pages.<名字>.id`。
4. **`entry_depth` = basic**：到此为止，给他 Notion 链接，说明「想要完整资料随时说『把这只写详细』」。
5. **`entry_depth` = full**：必须继续，别停在这里（这是最容易漏的一步）：
   1. 按 `skills/birding-notes/SKILL.md` §4 生成他启用的各模块内容（事实要有依据；没有可靠信息就写「（暂无）」，别编）。
   2. 找图并**看图确认**（§6.3）：`TOOLS find-images "<学名>"`，古画加 `--art --en "<英文名>"`；`TOOLS gbif "<学名>"` 取 GBIF 链接；鸣声用 `skills/birding-notes/scripts/xc_query.py "<学名>" --top 3` 选录音。
   3. 按 `skills/birding-notes/assets/entry_spec.template.json` 生成 spec，`TOOLS write-body <page_id> <spec.json>`。
   4. 看返回的 `warnings`：缺模块、无首图、配图失败都要处理或如实告诉他。
6. 把成果摆给他看：Notion 链接 + 一句话说明页面里有什么（几块、几张图、哪些没找到及原因）。**让他确认「这就是我想要的样子吗」**——不满意就当场按他说的调（比如嫌哪块啰嗦、想加或删某块），并更新对应偏好。

## 步骤 6：收尾小抄
再跑一次 `status`。给他一张小抄（用他听得懂的话，且只列他实际启用的能力）：
- 「记一只鸟：XX，在 YY，ZZ 号」
- 「把这个 Excel / eBird 导出导进来」
- 「把这只写详细」/「补下一批」
- 「查一下 XX 的学名 / 分类」
- 「我已经记了多少种？还有几种没有完整资料？」
- 「我想改成不要古画 / 多加一块……」（改偏好）

并告知：配置在 `~/.config/birding-notes/`（换电脑后再说一次「帮我开始观鸟记录」，会识别出已有的表并接上，不会重复建）；密钥只存在他自己的电脑上；鸣声录音以后想配 key 随时说。

## 排错
| 现象 | 处理 |
|---|---|
| 搜不到页面/表格 | 99% 是没授权给集成。重讲「···→连接」；刚新建的页面等几秒再试 |
| token 校验失败 | 没复制全（应以 `ntn_` 开头），或密钥已被重置 → 重新复制 |
| 网络超时 / SSL 断开 | 脚本已自动重试并轮换多个 IP；仍失败让他稍后重试或换网络，不要反复硬试 |
| 写入报 429 | 脚本自动等待重试；大批量改小批 |
| 找不到合适的图 | 对应位置留空，如实告知；别拿不确定的图凑数 |
| 配图上传失败（图过大等） | 换一张预览图；免费版 Notion 单文件约 5MB |
| 选项（目/科等）写不进去 | Notion 选项名不能含英文逗号，脚本已替换为中文逗号 |
| `status` 说缺字段映射 | 对现有库跑 `inspect` → 确认 → `map` |
| `status` 说缺条目偏好 | 回到步骤 2 的 Q3–Q4 问他，再保存 |
| 用户想换一张表 | 重走步骤 4（B 或 A），`set` 会覆盖旧的 ID |

## 其他 skill 如何接入
`birding-notes` / `avilist-bird-lookup` / `bird-batch-pipeline` / `notion-image-upload-migration` 在任何 Notion 操作前先跑 `status`；`ready: false` 就按本文件走向导，**配完回到用户原本的请求**，不要让他重新说一遍。写 Notion 时，列名一律以 `config.json` 的 `notion.fields` 映射为准，不硬编码；正文版式以 `birding-notes` §4、§6 为准。
